# 标签治理迁移说明（2026-11）

## 为什么要做

Archive 页标签云碎片化严重：**351 个唯一标签中 259 个只用了 1 次**（87% 的标签 ≤2 篇），
标签失去导航价值。目标：唯一标签数收敛到 150 以内（实际做到 **64 个**），并建立白名单机制防回流。

## 迁移规则（`tools/migrate_tags.py`）

1. **骨干标签**：使用频率 ≥3 的 44 个标签保留，其中 14 个改名统一（如 `AI加速→AI`、`MySql→MySQL`、`提示词模板→提示词工程`）；
2. **聚类映射**：其余 307 个碎片标签逐个映射到规范标签（同义词 / 上下位词归并），映射表完整写在 `tools/migrate_tags.py` 的 `CLUSTER` 字典，可逐条 review；
3. **噪音删除**：`基础`、`底层` 等无信息量标签直接删除；
4. **兜底**：映射后每篇文章至少保留 1 个标签（本次 0 篇落空）；同一篇内去重。

## 迁移结果

## 防回流

- `tools/tag_guard.py`：唯一标签数 > 150（可用 `--max` 调整）时退出码 1；
- `.github/workflows/tag_guard.yml`：改动 `_posts/**` 的 push / PR 自动执行。

以后写新文章请只从现有 64 个标签里选；确实需要新标签时，先确认它值得长期复用（预期 ≥3 篇），否则并入最近的规范标签。
